# But what if something urgent happens?

Imagine:

* Timer expires.

No.

# IPSR Register

The **IPSR (Interrupt Program Status Register)** tells the CPU which exception is currently running.

Examples:

```

```

→ Normal program execution (Thread mode)

```

```

Software or a debugger can read IPSR to know the current exception context.

# CMSIS Interrupt Numbers vs Exception Numbers

This often confuses beginners.

The architecture uses **exception numbers**, while the **CMSIS** library uses **IRQ numbers** for peripherals.

| Exception                   | Exception Number | CMSIS IRQ Number |
| --------------------------- | ---------------: | ---------------: |
| Reset                       |                1 |                — |
| NMI                         |                2 |              -14 |
| HardFault                   |                3 |              -13 |
| MemManage                   |                4 |              -12 |
| BusFault                    |                5 |              -11 |
| UsageFault                  |                6 |              -10 |
| SVC                         |               11 |               -5 |
| PendSV                      |               14 |               -2 |
| SysTick                     |               15 |               -1 |
| First Peripheral Interrupt  |               16 |                0 |
| Second Peripheral Interrupt |               17 |                1 |

So, **IRQ number 0 in CMSIS corresponds to exception number 16**.

---

# No FIQ in Cortex-M

Older ARM processors (such as ARM7TDMI) had two interrupt types:

* **IRQ** (normal interrupt)
* **FIQ** (Fast Interrupt)

FIQ existed to reduce response time for very urgent events.

Cortex-M processors removed the separate FIQ because they already have very low interrupt latency (around **12 clock cycles** for Cortex-M3/M4 under normal conditions), along with priority-based interrupt handling. This made a dedicated fast interrupt unnecessary.

---

# Reset Exception

Reset is unique.

After a reset:

* The processor starts executing the **Reset Handler**.
* It begins in **Thread mode** (not Handler mode).
* The **IPSR reads 0**, indicating normal execution rather than an active exception.

## Key points to remember

* **Exception** = any event that changes the normal execution flow.
* **Interrupt** = one type of exception, usually generated by peripherals.
* **NVIC** receives, prioritizes, and dispatches exceptions.
* **NMI** cannot be disabled and is reserved for critical events.
* **SysTick** is a built-in periodic timer commonly used by RTOSes and timing functions.
* **System exceptions** are exception numbers **1–15**.
* **Peripheral interrupts** start at **exception number 16**.
* The **vector table** maps exception numbers to handler addresses.
* The **IPSR** indicates which exception is currently active.
* Cortex-M processors do **not** have a separate FIQ because their interrupt response is already very fast.

# 4.5.2 Nested Vectored Interrupt Controller (NVIC)

## What is the NVIC?

Imagine a classroom.

* The **teacher** is the CPU.
* Students are **peripherals** (Timer, UART, ADC, GPIO, etc.).
* Students raise their hands when they need attention.

If all students shout at once, the teacher becomes confused.

So the school appoints a **class monitor**.

The monitor:

* Decides who should speak first.
* Keeps everyone in order.
* Prevents chaos.

The **NVIC** is that class monitor.

```text
                Cortex-M Processor

        +-----------------------------+
        |                             |
Timer -->|                             |
UART  -->|                             |
ADC   -->|            NVIC             |----> CPU Core
GPIO  -->|                             |
SPI   -->|                             |
I2C   -->|                             |
        +-----------------------------+
```

The CPU does **not** directly watch every peripheral.

Instead:

```text
Peripheral

↓

NVIC

↓

CPU
```

The NVIC manages all interrupt requests.

---

# Where is the NVIC located?

The book says:

> The NVIC is a part of the Cortex-M processor.

This means it is **built into the processor itself**.

It is **not** an external chip.

```text
+---------------------------------------------+

 Cortex-M Processor

   CPU Core

   ALU

   Registers

   NVIC

   SysTick

   Debug Unit

+---------------------------------------------+
```

So every Cortex-M processor already contains an NVIC.

---

# What does "programmable" mean?

The book says:

> It is programmable.

This means **you can configure its behavior using software**.

You can tell the NVIC:

* Clear a pending interrupt.
* Force an interrupt by software.

# What happens during preemption?

The book says:

> Some registers are stored on the stack.

Let's see the full sequence.

CPU executing:

```text
Instruction

↓

Instruction

↓

Instruction
```

Interrupt occurs.

The CPU automatically saves:

```text
R0

R1

R2

R3

R12

LR

PC

xPSR
```

onto the stack.

This is called **automatic stacking**.

Then:

```text

```

When ISR finishes,

the CPU automatically restores those registers.

Execution continues exactly where it stopped.

No software is needed for these save/restore operations.

Older processors required the programmer to save many registers manually inside every ISR.

Cortex-M hardware does it automatically, reducing execution time and code size.

```text

0x00000000 ---> Initial Stack Pointer

0x00000004 ---> Reset_Handler
```

When the Timer interrupt occurs, the processor reads the Timer entry from the vector table and jumps directly to `Timer_Handler`.

## PRIMASK

The book says:

> PRIMASK disables all exceptions except HardFault and NMI.

```text
↓
```

Imagine a factory.

Even during maintenance,

* watchdog expires
* serious hardware fault occurs

Therefore these exceptions remain active.

## BASEPRI Register

PRIMASK blocks **almost everything**.

BASEPRI is more selective.

Suppose:

| Priority | Interrupt      |
| -------- | -------------- |
| 0        | Emergency Stop |
| 1        | Fire Alarm     |
| 2        | Motor Control  |
| 3        | Timer          |
| 4        | UART           |
| 5        | ADC            |

If you set BASEPRI so that priorities **4 and below** are masked, then:

```text
Emergency Stop

Allowed

Fire Alarm

Allowed

Motor Control

Allowed

Timer

Allowed

UART

Blocked

ADC

Blocked
```

This lets urgent interrupts continue while delaying less important ones.

# CMSIS Makes It Easy

The book mentions **CMSIS-Core**.

CMSIS provides simple functions instead of making you write directly to NVIC registers.

Examples:

```c

NVIC_DisableIRQ(TIM2_IRQn);

NVIC_SetPriority(UART_IRQn, 2);
```

Without CMSIS, you would have to remember and write to specific memory-mapped register addresses, which is more error-prone.

# Summary

* **NVIC** is the built-in interrupt controller in every Cortex-M processor.
* It can **enable, disable, prioritize, and mask** interrupts.
* **Pending** means an interrupt has occurred but is waiting to be serviced.
* **Pulse interrupts** are remembered even after the pulse ends.
* **Level-triggered interrupts** stay active until the peripheral is serviced.
* **Nested interrupts** allow a higher-priority interrupt to interrupt a lower-priority ISR (preemption).
* **Automatic stacking/unstacking** saves and restores CPU registers without software overhead.
* The **vector table** lets the CPU jump directly to the correct interrupt handler.
* **PRIMASK** disables almost all interrupts, while **BASEPRI** blocks only interrupts below a chosen priority level.
* **CMSIS** provides simple API functions to configure and control the NVIC instead of accessing registers manually.

Understanding the NVIC is fundamental because **every peripheral interrupt in a Cortex-M microcontroller—timers, UART, SPI, I²C, ADC, GPIO, DMA, USB, and even most RTOS scheduling mechanisms—ultimately relies on the NVIC to decide when and how the CPU responds.**
